# Pac-Man

## Description

**Pac-Man** is a complete and playable recreation of the 1980 Namco arcade classic, written in **Python 3.10+** with an object-oriented, modular architecture and a simple graphical library (MLX or equivalent).

The goal of the project is to build a polished game that includes:

- Maze levels generated by an **external A-Maze-ing package** (assigned from another group, used as-is).
- A **JSON configuration file** (with comment support) to tune game parameters.
- A **persistent highscore system** (top 10).
- A full UI: main menu, in-game HUD, pause menu, game-over and victory screens.
- A **cheat mode** to make peer review easier.
- A **packaged build** published on a public platform (Itch.io / Steam, unlisted).

### Features

- 10+ levels, each with a time limit; score and lives carry over between levels.
- 4 ghosts (one per corner) that chase the player, flee when edible, and respawn after being eaten.
- Pacgums in the corridors and super-pacgums in the 4 corners.
- Pause / resume at any time.
- Robust error handling: no Python traceback is ever shown to the user.

### Controls

| Key | Action |
|---|---|
| Arrow keys / WASD | Move Pac-Man |
| SPACE | Start game (main menu) |
| P / ESC | Pause / resume |
| Enter | Validate menu choice / highscore name |

### Cheat mode

Cheat mode is meant for peer review. It is enabled with the key `C` at the main menu (or with the `cheat` option, see [Configuration](#configuration)). Once active, the following keys are available in game:

| Key | Cheat |
|---|---|
| `I` | Toggle invincibility (no life lost) |
| `N` | Skip level (immediately win it) |
| `F` | Toggle ghost freeze |
| `L` | Add an extra life |
| `+` / `-` | Increase / decrease player speed |

## Configuration

The game is configured through a JSON file passed on the command line. In addition to standard JSON, **comments are supported**:

- Lines starting with `#` are ignored (mandatory).
- `//` and `/* ... */` comments are also supported.

### Keys and default values

| Key | Type | Default | Description |
|---|---|---|---|
| `highscore_filename` | string | `"highscores.json"` | File where highscores are stored |
| `levels` | array | 10 levels | Per-level settings (see below) |
| `levels[].width` | int | `21` | Maze width for the level |
| `levels[].height` | int | `21` | Maze height for the level |
| `lives` | int | `3` | Starting lives |
| `pacgum` | int | `42` | Number of pacgums (as per subject suggestion) |
| `points_per_pacgum` | int | `10` | Score for a pacgum (X) |
| `points_per_super_pacgum` | int | `50` | Score for a super-pacgum (Y) |
| `points_per_ghost` | int | `200` | Score for an edible ghost (Z) |
| `seed` | int | `42` | Seed for the first level's maze |
| `level_max_time` | int | `90` | Time limit per level, in seconds |

> Adapt this table to the exact keys your implementation uses.

### Example

```jsonc
# Pac-Man configuration
{
    "highscore_filename": "highscores.json",
    "lives": 3,
    "points_per_pacgum": 10,
    "points_per_super_pacgum": 50,
    "points_per_ghost": 200,
    "seed": 42,
    "level_max_time": 90,
    "levels": [
        {"width": 15, "height": 15},
        {"width": 17, "height": 17}
    ]
}
```

### Faulty configuration handling

- Missing or invalid values are **clamped to safe defaults**, a clear message is logged, and the game continues.
- Unknown keys are ignored.
- A missing or unreadable file, or invalid JSON syntax, produces a clean error message and a proper exit (no traceback).

## Highscore

### How it works

- Highscores are stored in a **JSON file** (path set by `highscore_filename`).
- The **top 10** scores are kept, each with a player name and a score.
- Highscores are **loaded at game start** and **saved at game end** (win or lose).
- The player enters their name on the game-over / victory screen.
- Highscores are displayed in the main menu and in the "View Highscores" screen.

### Validation and robustness

- Names: maximum **10 characters**, alphanumeric characters and spaces only.
- Scores: non-negative integers.
- A missing file is created automatically; a corrupted or invalid file is handled gracefully (invalid entries are discarded, a message is logged, and the game continues with an empty/valid list).

### Why this design

A local JSON file is simple, human-readable, easy to inspect during peer review, needs no external dependency, and is easy to validate and recover from when corrupted.

## Maze Generation

Mazes are generated by the **A-Maze-ing package assigned to us by another group**. We do **not** write our own generator and we do **not** modify the package: our loader adapts to its interface.

- Package used: `<name / repository of the assigned package>`
- Generation parameters: width and height come from the configuration; `PERFECT` is set to `False` so the maze contains loops, producing Pac-Man-compatible corridors.
- **Level 1** uses a fixed seed (default `42`); **subsequent levels** use random seeds.
- A dedicated adapter/loader module converts the package output into our internal grid representation (walls, corridors, pacgum positions, super-pacgum corners, ghost corners, player start in the middle).
- If the generator fails (exception, invalid output), the error is caught and reported cleanly.

## General Software Architecture

```
.
├── pac-man.py              # Entry point: argument parsing, startup
├── config.json             # Default configuration
├── Makefile
├── README.md
├── pacman/
│   ├── config/             # Config loader (comments, validation, defaults)
│   ├── maze/               # Adapter to the A-Maze-ing package, grid model
│   ├── entities/           # Player, Ghost, Pacgum, SuperPacgum
│   ├── game/               # Game state, level manager, scoring, cheat mode
│   ├── highscore/          # Highscore storage and validation
│   └── ui/                 # Menus, HUD, screens, rendering (MLX)
├── tests/                  # Unit tests (not graded)
└── project_management/     # Project management documents
```

### Main modules and relationships

- **`pac-man.py`** reads the configuration, initializes the game, and launches the UI.
- **Config** provides validated settings to every other module.
- **Maze** wraps the A-Maze-ing package and produces a `Level` grid.
- **Game** owns the game state (current level, score, lives, timer) and coordinates **entities** (Player, Ghosts) each tick.
- **Highscore** is used by the game at start (load) and end (save), and by the UI to display scores.
- **UI** renders the game state and forwards user input; it does not contain game logic.
